# ADR Lifecycle

Follow the repository's statuses, metadata, numbering, filenames, and index
conventions. When none has been established, omit optional lifecycle metadata
rather than inventing a scheme.

Where local conventions use these statuses:

- **Proposed:** Open to material editing.
- **Accepted:** Requires an explicit acceptance decision; implementation or
  wording approval is insufficient.
- **Rejected:** Preserve the proposal and record the decision and material reason
  when local conventions use this status.
- **Superseded:** Identify the replacement, update links in both directions when
  the format supports them, and update any existing ADR index.

Do not silently change the meaning of an accepted ADR. Correct immaterial errors
when local policy permits; use a superseding ADR for a material decision change.

After file changes:

1. Re-read each affected ADR independently of the conversation.
2. Confirm statuses and lifecycle metadata reflect explicit decisions.
3. Search for stale filenames, numbers, titles, index entries, and links.
